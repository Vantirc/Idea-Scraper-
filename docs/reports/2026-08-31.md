# Business Idea Clusters from HN/Reddit Data

---

**Honest upfront note:** This dataset is thin. Most posts have very low engagement and no excerpts to analyze intent. Only **3 clusters** have meaningful signal. I'm not padding the rest.

---

## 🥇 1. Developer Burnout / Motivation Loss

**Pain point:** Developers and knowledge workers lose passion and motivation cyclically, with no structured tool to diagnose or recover from it.

**Evidence strength:**
- 1 post, but **164 engagement** — by far the highest in the dataset
- Extremely high relative to everything else; clearly resonated

**Who'd pay:** Indie hackers, senior devs, managers doing 1:1s, therapist-adjacent wellness apps

**Opportunity angle:** A structured self-assessment + recovery protocol tool (not generic journaling — something specific to technical burnout cycles). Think "Bearable app" but for developer motivation.

**Sources:**
- [Why do I lose my passion and want to do nothing?](https://news.ycombinator.com/item?id=49505014) — 164 engagement

---

## 🥈 2. Slides-as-Code / Docs Drift from Reality

**Pain point:** Presentation slides and documentation go stale and drift out of sync with the actual codebase, causing embarrassment and wasted maintenance time.

**Evidence strength:**
- 2 posts (SlideOps + AI-generated docs question), ~14 combined engagement
- SlideOps is a direct "I built this because the pain exists" signal
- The AI docs question shows people are actively worried about doc quality

**Who'd pay:** DevRel teams, engineering managers, developer educators, OSS maintainers

**Opportunity angle:** A CI/CD-integrated tool that flags when slides or docs reference code that has changed. SlideOps exists but is early-stage — the adjacent "AI-generated docs quality checker" is wide open.

**Sources:**
- [SlideOps – slides that flag when they drift from code](https://github.com/glukicov/slideops) — 9 engagement
- [Ask HN: How do you feel about AI generated documentation?](https://news.ycombinator.com/item?id=49505508) — 5 engagement

---

## 🥉 3. Multi-Session / Parallel AI Coding Agent Coordination

**Pain point:** Running multiple AI coding agents simultaneously creates context conflicts, duplicated work, and broken state — there's no good way to coordinate them.

**Evidence strength:**
- 2 posts directly on this theme, ~12 combined engagement
- Very specific technical ask ("biggest problems with multisession engineering")
- Decispher is another "I built this" signal validating the pain

**Who'd pay:** Senior engineers at AI-forward teams, solo founders using agents heavily, dev tooling companies

**Opportunity angle:** Persistent shared context/memory layer across parallel coding agent sessions — essentially a "project brain" that multiple agents can read/write safely.

**Sources:**
- [Ask HN: Biggest problems with multisession engineering?](https://news.ycombinator.com/item?id=49503285) — 7 engagement
- [Decispher – persistent engineering context for coding agents](https://news.ycombinator.com/item?id=49509142) — 5 engagement

---

The remaining posts (side project hosting, maps alternatives, Rust debate, VPS pricing, puzzle games, etc.) are **either too scattered, too low-engagement, or pure noise** to constitute validated business signals from this dataset.
