# Business Idea Clusters from HN/Reddit Data

---

## Honest Assessment First

This dataset is **thin**. Most posts have very low engagement (3–8 points), no excerpts to analyze intent, and many are noise. Only **3 clusters** have meaningful signal. I'm not padding to 8.

---

## 🥇 Cluster 1: LLM-Generated Code Trust & Validation

**Idea Name:** AI Code Review & Validation Layer

**Pain Point:** Developers using LLM-generated code have no reliable way to verify correctness — AI-written tests are circular (they defend the bugs they saw), and manual review is slow.

**Evidence:**
- "Does anyone find AI code review useful?" — eng. 10
- "Ask HN: How do you review and validate LLM generated code?" — eng. 8
- "The tests your agent writes defend the code it saw. Bugs included" — eng. 7
- 3 posts, ~25 total engagement, **very specific technical asks**

**Who'd Pay:** Engineering teams shipping AI-assisted code at scale; DevSecOps buyers at mid-to-large companies already paying for Snyk, SonarQube, etc.

**Sources:**
- https://news.ycombinator.com/item?id=49369710
- https://news.ycombinator.com/item?id=49378314
- https://news.ycombinator.com/item?id=49370920

## 🥈 Cluster 2: AI Token Cost Optimization at Orgs

**Idea Name:** Enterprise AI Token Usage Manager

**Pain Point:** Large organizations are burning unpredictable, uncontrolled budgets on LLM API tokens with no visibility or optimization tooling.

**Evidence:**
- "Idea to reduce AI token use at large orgs" — eng. 5
- "Ask HN: What AI automations have you kept running in production?" — eng. 5
- "Is this AWS RI/SP simulation engine interesting / valuable?" — eng. 3 *(analogous: cost simulation for cloud commitments)*
- 3 posts, ~13 engagement, **operationally specific**

**Who'd Pay:** CTOs and engineering VPs at companies with >$10k/month LLM spend; same buyer persona as cloud cost tools (CloudHealth, Spot.io).

**Sources:**
- https://news.ycombinator.com/item?id=49373930
- https://news.ycombinator.com/item?id=49373445
- https://news.ycombinator.com/item?id=49374412

## 🥉 Cluster 3: Frigate/Home Surveillance Camera Compatibility

**Idea Name:** IP Camera Compatibility Database

**Pain Point:** Home lab and prosumer users setting up open-source NVR software (Frigate) can't easily identify which IP cameras are compatible before buying.

**Evidence:**
- "Show HN: A data viewer for choosing Frigate-compatible IP cameras" — eng. **49** (highest in dataset)
- 1 post, but **highest single engagement by far**, and a working product already exists
- Signal: someone already built it and got traction, validating demand

**Who'd Pay:** Prosumer home security buyers, small business owners doing DIY surveillance, Frigate community (~100k+ users). Monetize via affiliate links on camera purchases or a premium filterable database.

**Sources:**
- https://github.com/ch-bas/cctv-camera-database
