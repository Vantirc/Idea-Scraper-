# Business Idea Signals from HN Data

**Honest upfront note:** This dataset is thin. Most posts have very low engagement (2–7 points), no excerpts, and many are conversational/off-topic. Only **3 clusters** have meaningful signal. I'm not padding to 8.

---

## 🥇 Cluster 1: Security for Small/Solo Developers

**Idea name:** Security Toolkit for Indie Devs

**Pain point:** Small developers lack accessible, affordable security guidance and tooling built for their scale — not enterprise.

**Evidence:**
- "Ask HN: Security for the Small Developer" (14 engagement)
- "Is it time to switch to Cybersecurity?" (5 engagement)
- "Ask HN: Getting around NPM typo squatting?" (2 engagement)
- 3 posts, ~21 total engagement, asks are **specific and recurring**

**Who'd pay:** Solo devs, indie hackers, small dev shops who ship to production but have no security team. Likely $10–$50/mo SaaS or a one-time audit tool.

**Sources:**
- https://news.ycombinator.com/item?id=50650947
- https://news.ycombinator.com/item?id=50648976
- https://news.ycombinator.com/item?id=50652314

## 🥈 Cluster 2: AI Agent Memory & Context Persistence

**Idea name:** Persistent Memory Layer for AI Coding Agents

**Pain point:** AI coding agents lose context across sessions and repos, forcing developers to repeat themselves or lose accumulated project knowledge.

**Evidence:**
- "Show HN: Dev-Mem – Local-first SQLite knowledge graph for AI coding agents" (3 engagement)
- "Ask HN: What IDE do you use and how many agents touch your tickets before merge?" (4 engagement)
- "Tell HN: Stop using MLX, start telling your agent to write custom kernels" (6 engagement)
- "Show HN: Graphvein – Trace calls to handlers and tables across repos, no LLM" (3 engagement)
- 4 posts, ~16 total engagement — **builders are actively shipping solutions**, which is a stronger signal than complaints alone

**Who'd pay:** Dev teams running multi-agent workflows, power users of Cursor/Claude Code/Copilot. B2B angle for engineering teams.

**Sources:**
- https://github.com/HarsH-1877/Dev-Mem
- https://news.ycombinator.com/item?id=50651107
- https://news.ycombinator.com/item?id=50648334
- https://github.com/graphvein/graphvein/

## 🥉 Cluster 3: Local-First Collaborative Tools (Obsidian-meets-Figma gap)

**Idea name:** Local-First Real-Time Collaboration Layer

**Pain point:** Users want the privacy/offline benefits of local-first apps (like Obsidian) AND real-time collaboration like cloud tools — nothing currently does both well.

**Evidence:**
- "Show HN: Hubris – Local like Obsidian, but real-time collaboration like Figma" (3 engagement)
- "Show HN: Dear Website – make and change a small website by email" (3 engagement, simpler local-first angle)
- 2 posts, ~6 engagement — **weak engagement but the problem statement is sharp and the builder framing it as Obsidian+Figma shows clear market awareness**

**Who'd pay:** Knowledge workers, small teams, privacy-conscious professionals. Obsidian's paid tier and Notion's growth confirm willingness to pay in this space.

**Sources:**
- https://hubris.live/
- https://dear.website/
